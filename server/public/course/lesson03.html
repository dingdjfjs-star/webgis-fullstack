第 3 课把 SQL 变成 API

前两课你写的 SQL 只有你自己能用。这一课学会把它包装成"网页也能调用的服务"——这就是后端 API。学完你将亲手给系统添加一个新接口。

1. API 是什么：餐厅比喻

浏览器（前端）和数据库之间隔着一层，谁也不直接见谁——就像顾客不会冲进后厨端菜。中间的服务员就是 API：

顾客"来一份火锅，微辣" —— 按菜单点前端
↓ 递单子（HTTP 请求）
服务员听懂需求 → 去后厨 → 把菜端回来装盘API（本课）
↓ SELECT ...
后厨真正做菜的地方，顾客看不见数据库
菜单 = 接口文档；点单 = 发请求；装盘上菜 = 返回 JSON 数据

关键理解：API 暴露的是有限的服务项目（菜单上没有的做不了），并且把内部的 SQL 细节藏起来。前端不需要会 SQL，只需要知道"点哪道菜、给什么参数"。

2. HTTP 一分钟：URL、参数、GET

浏览器和 API 之间的对话协议叫 HTTP。最常用的是 GET 请求——就是"在地址栏输入网址回车"那个动作。一个完整的 URL 长这样：

http://localhost:3000/api/pois/nearest?lat=30.593&lng=114.305&k=3
└──────┬─────┘└──────┬───────┘└────────┬────────────────────┘
     电脑+端口      路径(哪道菜)      查询参数(口味要求)
                                      ?参数名=值&参数名=值

三段式：主机（找谁）→ 路径（哪道菜）→ 查询参数（具体要求）。参数可以有多个，用 & 连接。API 收到请求后返回数据——现代 Web 返回的几乎都是 JSON 格式（长得像 JS 对象的文本，花括号+键值对）。

3. 调真实接口（点链接就能玩）

我们系统的 API 已经在跑了。下面每行文字都是真实链接，点开就在浏览器里完成了一次 API 调用（返回原始 JSON——浏览器就是最朴素的 API 调试工具）：

这道菜点单链接
离市政府最近的 3 家店（KNN）/api/pois/nearest?lat=30.593&lng=114.305&k=3
市政府 1 公里缓冲区统计/api/pois/buffer?lat=30.593&lng=114.305&r=1000
全城分类统计/api/pois/summary?bbox=...
流域全部监测站/api/basin/stations

做两件事加深体感：① 把 k=3 改成 k=10 再回车；② 把 lat 随便改个数，观察返回的 dist_m 怎么变。你正在做的事，和 POI 系统前端背后做的事一模一样——只不过它用代码调，你用鼠标调。

bbox 是什么？bounding box（范围框），4 个数字"西,南,东,北"围出一个矩形——就是地图当前视野。POI 系统里你每拖一下地图，前端就发一个新 bbox 的请求。

4. 读懂真实路由代码

这些接口是谁写的？就是普通 JS 文件。server/src/routes/pois.js 里"最近邻"接口长这样（简化了过滤逻辑，骨架原样）：

pois.get('/nearest', async (req, res, next) => {
  try {
    const { lat, lng } = req.query;      // ① 从 URL 取参数
    const k = Math.min(+(req.query.k || 10), 50);  // ② 默认10个，最多50
    const p = [+lng, +lat];              // ③ 参数数组（$1,$2 占位）
    const { rows } = await query(
      `SELECT name, ST_X(geom) x, ST_Y(geom) y,
              ST_Distance(geom::geography,
                ST_Point($1,$2,4326)::geography)::int AS dist_m
       FROM poi.pois
       ORDER BY geom <-> ST_Point($1,$2,4326)
       LIMIT $3`, [...p, k]);            // ④ 执行 SQL（第2课的KNN！）
    res.json({ type: 'FeatureCollection', features: ... }); // ⑤ 装盘返回
  } catch (e) { next(e); }               // ⑥ 出错交给统一错误处理
});

逐个零件认识：

代码意思
pois.get('/nearest', fn)注册一条规则：GET /api/pois/nearest 的请求由这个函数处理（get 是"查询"，新建数据会用 post）
req.queryURL 里 ? 后面的参数，打包成的对象；req 是"请求"
$1, $2, $3参数化查询占位符。值不拼进 SQL 字符串而是单独传——防 SQL 注入攻击，也自动处理引号
res.json(数据)把结果转成 JSON 返回给调用方；res 是"响应"
try/catch/next(e)出错时不让服务崩溃，转给统一的错误处理器返回 500
看懂这个函数，你就看懂了整个后端：所有 19 个接口都是这个骨架，只是 SQL 不同。后端开发 = 收参数 → 拼 SQL → 返回 JSON 三板斧。

5. 亲手加一个端点（本课大作业）

光看不算会。现在给系统真的加一个新接口：GET /api/pois/count —— 返回视野内的 POI 数量（POI 系统右上角那个数字就是它的原型）。

第 1 步：打开文件

用记事本（或 VS Code）打开 E:\zcode\server\src\routes\pois.js，拉到文件最末尾，粘贴这段代码：

/** 【第3课练习】视野内 POI 计数：GET /api/pois/count?bbox=&categories= */
pois.get('/count', async (req, res, next) => {
  try {
    const p = [];
    const c = [];
    if (req.query.bbox) {
      const [minx, miny, maxx, maxy] = String(req.query.bbox).split(',').map(Number);
      p.push(minx, miny, maxx, maxy);
      c.push(`p.geom && ST_MakeEnvelope($1,$2,$3,$4,4326)`);
    }
    if (req.query.categories) {
      p.push(String(req.query.categories).split(','));
      c.push(`p.category = ANY($${p.length})`);
    }
    const where = c.length ? 'WHERE ' + c.join(' AND ') : '';
    const { rows } = await query(
      `SELECT count(*)::int AS cnt FROM poi.pois p ${where}`, p);
    res.json({ count: rows[0].cnt });
  } catch (e) { next(e); }
});

这段代码你已经全都见过：bbox 拆成 4 个数（第 3 课）、&& 范围相交（第 2 课）、参数化占位符（本课）、GROUP BY 都不需要因为只要总数（第 1 课）。

第 2 步：重启服务

Node 不会自动感知代码变化：找到 server 那个黑窗口，按 Ctrl+C 停掉，重新运行 E:\zcode\scripts\start-all.bat（或那个窗口里 npm start）。

第 3 步：验收

浏览器打开（保存后这是真实链接，前提是你完成了第 1、2 步）：

http://localhost:3000/api/pois/count?bbox=114.08,30.44,114.56,30.72
http://localhost:3000/api/pois/count?bbox=114.08,30.44,114.56,30.72&categories=餐饮

第一条应返回 {"count":250000}（全城），第二条约 6 万（餐饮约占 24%）。看到数字，恭喜——你已经是能给系统添加接口的人了。

改了代码没重启 → 接口 404；重启了还是 404 → 检查代码是不是粘到了文件末尾、pois.get 有没有拼错。看 server 黑窗口的报错信息，第一行通常直接指出错在第几行。

6. 练习 + 打卡

练习 1（浏览器完成）

调 /api/basin/stations，在返回的 JSON 里数一数：grade 为 5（Ⅴ 类，红色预警站）的有几个站？它们的名字是？

查看答案
2 个：临江·工业走廊站（WQ009）和 临江·入湖口站（WQ010）——正好是数据设计时"下游工业段退化最严重"的两站。真实工作里这个"从 JSON 里找信息"的活，以后就是前端代码用 JS 自动干的。

练习 2（改代码）

给刚写的 /count 端点再加一个参数：&kw=医院 时只统计名字/子类含"医院"的。提示：照抄 categories 的写法，条件用 (p.name ILIKE $n OR p.subcategory ILIKE $n)，ILIKE 是不区分大小写的模糊匹配（%配任意字）。

查看答案
if (req.query.kw) {
  p.push(`%${req.query.kw}%`);
  c.push(`(p.name ILIKE $${p.length} OR p.subcategory ILIKE $${p.length})`);
}
改完重启，访问 ?bbox=全城&kw=医院 应约 4000+ 个。注意同一个占位符 $n 只能对应一个参数，所以值要 push 两次。
本课速查卡：URL = 主机+路径+?参数 ｜ GET=查询 ｜ 返回 JSON ｜ 路由骨架 = req.query 收参 → 参数化 SQL → res.json ｜ 改代码必须重启 ｜ 参数化 $1 防 SQL 注入。
