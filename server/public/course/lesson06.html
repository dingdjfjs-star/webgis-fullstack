第 6 课数据从哪来：造出 25 万个点

这 25 万个 POI 不是爬来的，是程序生成的——但它们"像真的"：市中心挤、主干道沿线成串、类别比例符合常识。这课教你造数据的手艺，以及为什么"像真的"本身是一门学问。

1. 为什么不能"均匀随机"

造 25 万个点最省事的写法是 经度 = 114.08 + 随机数×0.48，纬度同理。试想那样会发生什么：点在地图上撒得像均匀的细沙，热力图一片平、CBD 不存在、"市中心餐饮多"这种分析结论全是假的——分析系统的好看与否，在数据生成的瞬间就决定了。

真实城市的设施分布有强烈的空间结构：中心密度高、边缘低，沿交通线集聚，不同类别聚集规律不同（学校挨居民区、4S 店在城市边缘）。造数据 = 把这些结构写进代码。

2. 混合空间模型：25 万个点住在四种地方

server/scripts/seed.js 里每个 POI 的出生地由一个"抽签"决定：

抽中概率出生地代码怎么写模拟什么
45%3 个 CBD 中心附近中心点 + 高斯偏移 σ=0.008°（≈800 米）核心商圈（极度聚集）
35%6 个区中心附近中心点 + 高斯偏移 σ=0.02°（≈2 公里）区级生活圈
15%40 条"主干道"沿线随机取一条折线，在线上随机取点，垂向抖动 120 米沿街商铺成串
5%全域任意位置均匀随机乡村零星设施

两个新词当场解释：

  • 高斯偏移（正态分布）：钟形概率——离中心越近的点越多、越远越少，但不像圆盘那样"一刀切"。生活里"住公司附近的人"就是这么分布的。代码里 randn() 一次生成一个正态随机数；σ（西格玛）是"典型散开程度"，σ 越大越分散。
  • 沿折线采样：先造 40 条随机走向的折线当"主干道"（走向以东西/南北为主、混少量斜路），POI 先选一条路，再在线上选一个位置，最后垂直方向抖 100 来米——这就是你看到的"沿路成串"的店。

3. 确定性随机：种子 20260829

普通随机数每次运行都不同——数据变了，第 8 课那些"六边形总和必须等于 25 万"的测试就没法写死。所以 seed.js 不用 Math.random()，而是用种子随机（mulberry32 算法）：

const rng = mulberry32(20260829);   // 播下这颗"种子"
const rand = () => rng();           // 以后每次 rand() 得到的序列都一样

种子固定 → 随机序列固定 → 今天生成和明年生成，25 万个点一模一样。这带来三个好处：① 测试可以写精确断言；② 数据坏了可复现排查；③ 讲义里的每个数字（7202、44984）你都能跑出一模一样的值。

4. 26 秒灌 25 万行的秘密：COPY

往表里塞数据有两种方式。笨办法是一条条 INSERT：INSERT INTO poi.pois VALUES (...)，每条都要数据库走一遍完整流程，25 万条要等上几分钟。快办法是 COPY——把数据拼成一个大文本流（CSV 样式），数据库像吸面条一样一口气吸进去：

// seed.js 的真实做法（pg-copy-streams 库）
const stream = client.query(
  copyFrom.from('COPY poi.pois (name,category,...,geom) FROM STDIN WITH (FORMAT csv)'));
for (每 2 万行一批) {
  stream.write(这一批拼成的文本);      // 几何直接写 WKT：POINT(114.3 30.5)
}
stream.end();

实测：25 万 POI 8.7 秒、8.8 万行时序 2.3 秒。批量导入永远用 COPY，这是数据库工程的常识。导完还有两步收尾：UPDATE 回填每个点属于哪个区（空间连接），ANALYZE 让数据库重新摸底统计（不摸底，优化器会瞎选执行计划）。

5. 水质时序的"剧本"

流域平台那 8.76 万行水质数据是照着一个"剧本"演出来的——每条曲线 = 四种成分叠加：

成分规律演示效果
季节项冬季水温低、复氧强 → 溶解氧高DO 曲线冬天爬高
昼夜项白天光合作用产氧 → pH/DO 午后高曲线每天一个小波浪
站点退化梯度给每站一个系数 d：上游 0 → 下游 1.05，氨氮 = 0.30 + 1.35×d"上游 Ⅱ 类、下游 Ⅴ 类"自动成立，预警自动指向工业段
降雨冲刷事件随机暴雨 → 2 小时后浊度暴涨、氨氮升高、DO 下降降雨-水质响应图出现关联尖峰
注意剧本的巧思：结论不是硬编码的——代码没写"下游站是Ⅴ类"，只写了退化系数；"下游超标"是分级函数（GB 3838）作用在数据上自然涌现的。造数据的高境界：定规则，不定结论。

7. 动手改数据 + 练习 + 打卡

真实实验：把餐饮权重从 24% 调到 40%。用记事本打开 E:\zcode\server\scripts\seed.js，找到约第 60 行：

{ name: '餐饮', w: 0.24, ... }

把 0.24 改成 0.40（别的权重不用动，抽签算法按比例自适应）。然后在 server 目录执行：

npm run seed

约 26 秒后重灌完成（幂等设计，随时可重来；不满意改回来再跑一遍即可）。刷新 POI 系统，饼图立刻变成"餐饮占四成"。跑一次试试，再改回来。

seed 会清空并重建两套系统的所有数据。你自己在库里加的测试数据会没——学习阶段无妨，正式开发要懂得先备份。

练习 1（口头）

为什么造数据用"种子随机"而不是 Math.random()？

查看答案
种子固定则数据完全可复现：测试能写精确断言（六边形总和=25万）、bug 能重现、讲义数字你都能跑出同款。工程上这叫"确定性"——看似随机，实则受控。

练习 2（改代码）

把 CBD 的高斯 σ 从 0.008 调成 0.03，重新 seed 后热力图会变成什么样？先在脑内预测，再实验验证。

查看答案
热团从"紧凑的三个红核"散成"三个大而模糊的暖区"（σ=0.03°≈3.3 公里，已经和区中心 σ 一样大，两个 CBD 会糊成一片）。这个实验说明：σ 参数直接控制聚集强度——密度分析里的"聚类尺度"在数据侧就是这个旋钮。
本课速查卡：均匀随机=假数据 ｜ 混合模型=45% CBD高斯+35%区中心+15%沿路+5%均匀 ｜ σ=散开程度 ｜ 种子随机=可复现 ｜ 批量导入用 COPY ｜ 导完 ANALYZE ｜ 时序=季节+昼夜+退化+降雨剧本，定规则不定结论。
