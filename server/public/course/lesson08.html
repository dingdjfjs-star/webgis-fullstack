1. 为什么要测试

场景：你给 /count 端点加了个参数（第 3 课作业），手一滑把别的 SQL 改错了。界面上东点点西点点，看起来都正常——但"最近设施检索"悄悄坏了。没有测试，这种 bug 可能两周后才被用户发现。

测试 = 写一段代码，自动调用你的接口并检查结果对不对。每次改完代码跑一遍，几秒钟内知道有没有弄坏东西。它不是额外负担，是让你敢于改代码的安全网。

2. 我们的 16 条测试长什么样

测试文件在 server/test/api.test.js，用 Node 自带的测试器（不用装任何东西）。跑法：

cd E:\zcode\server
npm test

输出长这样（你以后看到的应该全是 ✔）：

✔ 健康检查返回 PostGIS 版本 (105.0ms)
✔ 视野 POI 查询：GeoJSON 结构与上限约束 (10.4ms)
✔ 六边形密度：格网计数总和等于 POI 总数 (595.9ms)
✔ 全局 Moran's I：显著空间聚集 (492.1ms)
...
ℹ tests 16  ℹ pass 16  ℹ fail 0

单个测试的写法（Node 自带 node:test + assert 断言库）：

import { test } from 'node:test';
import assert from 'node:assert/strict';

test('KNN 最近邻：按距离递增返回', async () => {
  const res = await fetch('http://localhost:3000/api/pois/nearest?lat=30.593&lng=114.305&k=5');
  const body = await res.json();
  assert.equal(body.features.length, 5);              // 断言1：正好5条
  const d = body.features.map(f => f.properties.dist_m);
  for (let i = 1; i < d.length; i++)
    assert.ok(d[i] >= d[i-1] - 1e-6);                 // 断言2：距离不递减
});

真正值得学的不是语法，是断言什么。我们不满足于"返回 200"，而是断言业务不变量——无论代码怎么改、数据怎么重灌都该成立的事实：

不变量抓住什么 bug
六边形格网计数总和 == 250000聚合 SQL 少算/漏掉点（比如 LEFT JOIN 写成 JOIN 丢点）
KNN 结果距离单调不减排序写错、索引误用
上游站等级 < 下游站等级GB3838 分级方向写反（我们在开发中真犯过这个错！）
缓冲区源 dist_m ≤ 查询半径距离单位/类型错误

这些断言之所以敢写死数字，靠的正是第 6 课的种子随机——数据可复现，结果才可断言。课程里的知识是咬合在一起的。

3. 性能基准：索引快 100 倍是怎么量出来的

第 2 课给过一张表（KNN 快 100×），它由 server/test/bench.js 生成：

npm run bench

基准方法学（这三步是业界通用的）：① 同一条 SQL 在正常态跑 5 次取中位数（排除偶发抖动）；② 用 SET enable_indexscan=off 等开关逼数据库走全表扫描再跑 5 次；③ 两边相除得加速比，结果落盘成 Markdown 表（docs/perf.md）。

为什么取中位数而不是平均值：慢的那几次可能被磁盘缓存、后台进程干扰，中位数抗离群值。做性能对比时永远多跑几次。

4. 一次真实的调优复盘

给你讲一个本系统开发时真实发生的性能事故，比理论课有用十倍：

现象：缓冲区分析（1 公里圈）要 268ms，基准显示它和全表扫描差不多快——索引形同虚设。

排查：EXPLAIN 一看，走的是 Seq Scan。为什么？SQL 写的是 WHERE ST_DWithin(geom::geography, ...)——在列上做类型转换。索引目录是按 geom 原样编的，"变形后的列"对不上号，优化器只好放弃目录。

药方：为变形后的形态单独建一本目录——表达式索引：

CREATE INDEX pois_geom_geog_gist ON poi.pois USING gist ((geom::geography));

疗效：268ms → 100ms（2.4×）。这条经验被写进了建库 SQL 的注释里，也写进了课程的坑卡。

通用方法论：感觉慢 → EXPLAIN 看计划 → 发现 Seq Scan → 查"列有没有被函数/转换包裹" → 建匹配的表达式索引 → 再 EXPLAIN 验证 → 用基准记录前后对比。面试里能完整讲出这个链条，比背十个名词值钱。

5. 毕业项目

三个题目选一个（推荐第 1 个），做出你自己的全流程系统：

题目 A：某市共享单车停放点空间分布分析 ⭐推荐

表：停放点（点，含车辆数/类型）、行政区（面）、早晚潮汐计数（时序）。分析：热点格网、各行政区供给均衡度、地铁站 300 米覆盖率（ST_DWithin）。前端：Leaflet 聚合 + 覆盖圈。

题目 B：学区覆盖分析

表：学校（点，含学位数）、小区（点，含户数）、学区划分。分析：每个小区最近学校（KNN）、学位供需比按区聚合、2 公里入学圈覆盖率。

题目 C：污染源溯源辅助

在现有流域库上扩展：某站超标时，找出其上游 5 公里内全部污染源（沿河线缓冲+方向判断），按负荷排序输出"嫌疑清单"。

无论选哪个，验收标准都是这套（也是真实工作的交付清单）：

  • 建表 SQL（含空间索引 + 一条"为什么建这个索引"的注释）
  • 种子数据（种子随机、有空间规律、≥5 万行）
  • ≥2 个分析端点（参数化查询、错误处理）
  • 1 个地图页（视野联动 + 弹窗）
  • ≥3 条含业务不变量的测试，全部通过
  • README：一段架构图 + 一张性能对比表

做完后对我说「批改毕业项目」，我按这个清单逐项检查。
